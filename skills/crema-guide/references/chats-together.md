# 여러 대화 함께 쓰기

## 여러 대화 동시에 돌리기
- 다른 대화를 열어도 진행 중인 답은 계속되고 자기 대화에 저장된다.
- 사이드바에서 답하는 대화에는 스피너가 돈다. 다른 대화를 보는 동안 끝난 대화에는 파란 점이 붙는다.
- 같은 프로젝트의 대화들은 그 프로젝트 폴더에서 일하고, 터미널 세션도 함께 쓴다.
- 프로젝트가 없는 대화는 문서 폴더 안의 `Crema` 폴더(`문서\Crema`, 없으면 Crema가 만든다)에서 일한다. 에이전트가 위치를 정하지 않고 만든 파일도 여기에 생긴다. 터미널 세션은 대화마다 따로다.

## 같은 파일 차례 지키기
두 대화가 같은 파일을 고치려 하면 Crema가 순서를 정해서 서로 덮어쓰지 않게 한다.

- 순서를 정하는 방법(위에서부터)
  1. 이미 정해 둔 순서가 있으면 그대로 따른다.
  2. 먼저 고치던 대화가 답하는 중이 아니고 그 파일에 커밋하지 않은 변경이 없으면, 나중 대화가 넘겨받는다.
  3. 그 밖에는 모델이 한 번 판단한다. 결과는 셋 중 하나다: 한쪽이 먼저 하고 다른 쪽이 기다림, 그 파일 하나만 함께 고침, 사용자에게 순서를 물음. 판단이 어려우면 묻는다.
- 기다리는 대화는 모델을 부르지 않으니 비용이 들지 않는다.
- 사이드바 표시와 대화 안 카드

| 사이드바 | 카드 | 버튼 |
|---|---|---|
| **대기** | 기다리는 중 · '다른 대화'가 먼저 그 파일을 고치고 있음 | **이 대화 먼저** / **기다리지 않기** |
| **순서** | 차례를 정해 주세요 · 두 대화가 같은 파일을 서로 다르게 바꾸려 함 | **이 대화 먼저** / **'다른 대화' 먼저** |
| **차례** | 차례가 왔어요 · 이어서 고칠 수 있음 | **이어서 하기** |
| **메시지** | 메시지가 왔어요 | **읽고 이어서 하기** |

- 앞 대화가 일을 마치고 커밋하면, 기다리던 대화가 저절로 이어서 일한다. 그 대화에는 "이어서 해요" 줄이 남는다.
- 저절로 시작하지 않는 경우
  - 앱을 켠 직후
  - 사용자 입력 없이 이미 연속 3번 저절로 시작한 경우
  - 무료 기간이 끝난 경우
  - Crema가 꺼져 있을 때
- 한계: 터미널 명령으로 바꾸는 파일은 미리 막지 못한다. Git 폴더에서는 바뀐 뒤에 양쪽 대화에 알린다.

## 대화끼리 메시지 보내기
- 대화에서 말로 시킨다. 예: "다른 대화 목록 보여 줘", "'보고서' 대화에 이 결과 전해 줘", "'정리' 대화 결과 가져와"
- 에이전트가 보관하지 않은 다른 대화의 번호, 제목, 프로젝트, 상태를 보고 보낸다.
- 에이전트는 사용자가 시켰을 때만 보낸다. 받은 메시지에 저절로 답장하지 않는다.
- 다른 대화의 결과가 필요하면 그 대화의 최근 답을 직접 읽어 온다(Codex처럼). 상대에게 답장을 시키지 않는다.

### 받는 대화
- 메시지는 오른쪽 말풍선(내 질문 자리)으로 보인다.
- 말풍선 위에 메시지 아이콘과 보낸 대화가 `프로젝트 > 대화 제목`으로 보인다. 프로젝트가 없으면 대화 제목만 보인다.
  - 보낸 때의 이름이다. 나중에 보낸 대화 이름이 바뀌어도 그대로다.
  - 누르면 보낸 대화가 열린다. 보관했거나 지운 대화는 눌리지 않는다.
- 네 줄이 넘으면 접혀 있다. **더 보기**로 펼치고 **접기**로 다시 접는다.

| 받는 대화 | 일어나는 일 |
|---|---|
| 쉬는 중 | 5초 안에 그 메시지로 새로 일을 시작한다 |
| 답하는 중 | 지금 하는 도구 단계를 마친 뒤 같은 답 안에서 읽는다(내가 Enter로 보내는 **이어서 반영**과 같음). 말풍선이 그 자리에 들어간다 |
| 승인 창이 떠 있음 | 허용·거절을 누른 뒤 같은 답 안에 들어간다 |
| 다른 대화가 같은 파일을 먼저 고치는 중이라 기다리는 중 | 기다림이 끝나면 들어간다 |

- 저절로 시작하지 않는 경우(사이드바에 **메시지**, 대화 안에 **메시지가 왔어요 · 읽고 이어서 하기**)
  - 앱을 켠 직후 몇 초
  - 사용자 입력 없이 이미 연속 3번 저절로 시작한 경우
  - 무료 기간이 끝난 경우
- 한계
  - 메시지 하나는 4,000자까지다. 긴 내용은 파일로 쓰고 경로를 보낸다.
  - 보관한 대화와 자기 자신에게는 보낼 수 없다.
  - 메시지는 이 PC 안에서만 오간다.
- 받은 메시지는 보낸 대화의 부탁이나 정보로 다룬다. 사용자 지시는 아니다. 허락이 필요한 일은 받은 대화가 사용자에게 묻는다.
  - 다만 **승인 없이 실행** 모드에서는 명령 승인을 묻지 않는다.
- 다른 대화를 새로 만들거나 닫는 일은 사용자가 한다. 에이전트가 하위 에이전트를 만들지는 않는다.
