# 모델과 연결

## Crema와 AI의 관계
- Crema는 모델을 제공하지 않는다. 사용자가 이미 가진 AI 계정을 연결한다.
- AI 사용료는 연결한 AI 계정에서 따로 나간다. Crema 요금에는 들어 있지 않다.
- Crema는 남은 한도나 사용 시간을 보여 주지 않는다. `/usage`는 이 대화의 토큰 수와 예상 비용만 보여 준다.
- 키와 로그인 정보는 이 PC에만 저장된다. Crema 서버로 보내지 않는다.
- Crema에서 직접 연결한 것만 쓴다.
  - 다른 프로그램(Claude Code, Codex CLI, GitHub CLI)의 로그인은 가져다 쓰지 않는다. 그 로그인을 같이 쓰면 한쪽이 로그아웃될 수 있다.
  - Windows 환경 변수에 넣어 둔 API 키(`OPENAI_API_KEY` 등)도 쓰지 않는다. 그 키로만 쓰던 AI는 모델 목록에 나오지 않으니, 설정 › AI 연결에서 키를 넣어 연결한다.

## AI 연결하기
설정 › AI 연결 › Provider 선택 › **Provider 추가**에서 한다.

1. 처음 열 때는 목록을 불러오는 데 20초쯤 걸린다.
2. 검색 칸에 이름을 치거나 묶음에서 고른다.
   - 많이 쓰는 AI: ChatGPT (OpenAI), Claude (Anthropic), Gemini (Google), Grok (xAI), GitHub Copilot, Meta AI
   - 여러 AI를 한 곳에서: OpenRouter, AI Gateway, Kilo Code, OpenCode, Nous 등
   - 오픈소스 모델 서비스: Groq, Mistral, Hugging Face, Fireworks 등
   - 중국 AI: DeepSeek, Qwen, Kimi, GLM, MiniMax 등
   - 기타(개발자·기업용)
3. 고르면 인증 방식과 그 단계가 나온다.

| 방식 | 하는 법 |
|---|---|
| **API 키** | 키를 붙여넣고 **확인하고 저장**. **키 발급 페이지**가 키 만드는 곳을 연다. 확인할 수 있는 AI는 키를 먼저 확인하고, 거절하면 저장하지 않는다. 확인 방법이 없는 AI는 확인 없이 저장한다 |
| **구독 – 기기 코드** (ChatGPT, Grok, MiniMax, Nous 등) | **로그인 페이지 열기** → Crema가 보여 주는 코드를 그 페이지에 넣고 승인 → 저절로 끝난다 |
| **구독 – 코드 붙여넣기** (Claude) | **로그인 페이지 열기** → 승인하면 나오는 코드를 Crema에 붙여넣고 **연결** |

- 이미 연결한 AI는 "연결됨"으로 보이고 다시 누를 수 없다.
- 목록에 없는 것
  - LM Studio(내 PC 모델), Claude Code 로그인
  - Amazon Bedrock, Google Vertex
  - 터미널에서 로그인해야 하는 구독(Qwen, Copilot 구독). 이것들은 API 키나 토큰으로만 연결한다.
- 연결을 끊거나 지우는 화면은 없다.
- 로그인이 만료된 AI는 모델 목록에서 저절로 빠진다. 같은 곳에서 다시 연결하면 된다.

### Crema가 안내하며 연결
- 가입이나 키 발급 사이트를 Crema 안에 띄운다. 왼쪽은 안내와 주고받는 대화, 오른쪽은 그 사이트 화면이다. 위에는 무엇을 연결하는지가 나오고, 안내하는 동안 사이드바는 접힌다.
- 사이트 화면은 보기만 한다. 화면을 눌러도 닿지 않는다(주소 줄 옆에 "고르기 · 입력은 대화창에서 해요"). 고르기와 입력은 모두 왼쪽 대화창에서 하고, Crema가 그대로 화면을 누르고 입력한다.
- 안내는 차례를 주고받으며 나아가고, 한 번에 하나만 묻는다.
  - 고르기: 대화창에 단추가 나온다. 고르면 Crema가 화면의 그 버튼을 누르고 대화에 "‘○○’를 눌렀어요"를 남긴다. 화면에는 고르면 누를 곳이 주황 테두리와 "고르면 이걸 눌러요"로 표시된다. 고를 것이 여럿이면 테두리 안에 번호가 붙고 대화창 단추에도 같은 번호가 붙는다. 단추에 마우스를 올리면 화면의 그 번호가 커진다. 만들기·허용·저장처럼 누르면 결과가 남는 단추도 사용자가 고른 뒤에만 누른다. 이미 있는 프로젝트를 쓸지 새로 만들지처럼 화면에서 누를 것이 없는 질문도 단추로 묻는다.
  - 입력: 대화창 입력칸 위에 칸 이름이 나오고, 화면의 그 칸이 "적은 값이 여기에 들어가요"로 표시된다. 적고 Enter를 누르면 Crema가 그 칸에 있던 값을 지우고 넣는다. 비밀번호·키 칸이면 입력칸이 가려지고 대화에는 ••••••로 남는다. 그 값은 crema-agent.site로 보내지 않는다. 적지 않고 물어보려면 **적는 대신 물어보기**를 누른다.
  - 직접 하는 일: 로봇 확인, 휴대폰·보안 키 확인, 화면의 값을 복사하는 일, 펼침 목록에서 고르는 일처럼 사람만 할 수 있는 일은 그때만 화면이 풀린다(주소 줄 옆 "직접 하는 중", 화면 둘레에 검은 테두리). 하고 나서 **다 했어요**를 누른다. 시간이 얼마나 걸려도 Crema는 기다린다.
  - 모르는 것이 있으면 입력칸에 적어 보낸다(예: "‘만들기’가 안 보여요").
  - Crema 차례: Crema가 누르거나 입력한 뒤 화면이 멈추면(바뀜과 불러오기가 0.5초 동안 없으면) 그 화면을 보고 다음에 물을 것을 정한다. 누르는 동안 "화면에서 하고 있어요…", 정하는 동안 "다음에 할 일을 살펴보고 있어요…"가 뜬다.
- 칸에 들어 있는 값도 보고 안내한다. 안내와 다른 값이면 그 칸을 다시 묻는다.
- 대상: Gemini, Groq, OpenRouter, ChatGPT 구독, Claude 구독, Brave 검색, 메일(지메일·네이버·다음·카카오), 구글 캘린더, 구글 드라이브
- 화면에 키가 나오면 Crema가 찾아서 **Crema에 넣기** 버튼을 밝힌다(메일의 앱 비밀번호는 바로 받는다). 찾지 못하면 안내가 붙여넣으라고 말하고 그 칸이 나온다(복사하는 동안 화면이 풀린다). 복사해 붙여넣고 **Crema에 넣기**를 누른다.
- 넣은 키를 그 회사가 받지 않으면 "이 키는 쓸 수 없어요. 새 키를 만들어야 해요."가 대화에 남고, 안내가 새 키를 만드는 쪽으로 묻는다.
- 연결이 끝나면 안내가 닫히고, 대화에 Crema의 답처럼 "○○ 연결을 마쳤어요"와 이제 쓸 수 있는 기능이 남는다.
- 안내는 한 시간에 부를 수 있는 횟수에 제한이 있다. 넘으면 "안내 요청이 너무 많았어요"가 나오고, 잠시 뒤 **다시 해 보기**를 누르면 이어서 안내한다.
- 안내를 위해 crema-agent.site로 보내는 것은 그 사이트 화면에 보이는 글과 버튼·칸 이름, 화면 구조(영역·제목, 고를 것을 골랐는지, 칸에 들어 있는 값, 꼭 채워야 하는지)를 위에서 아래 순서로 적은 것, 페이지 주소(뒤의 조회값 제외)·제목, 오류 문구다. 이메일, 긴 숫자, 키처럼 생긴 글자는 가려서 보내고, 비밀번호 칸은 값을 보내지 않는다. 여기에 안내가 한 말, 사용자의 대답(**다 했어요**, 고른 대답, 입력칸에 적은 값, 직접 쓴 말)과 Crema가 화면에 한 일을 더해 crema-agent.site가 OpenAI의 GPT에 보내 할 일을 정한다. 화면 내용과 대답은 저장하지 않는다. 가려 적은 비밀번호·키는 보내지 않는다. 다음 사람을 안내할 때 참고하려고 화면의 종류(주소 경로와 제목·칸 이름으로 만든 요약값)와 그때 고르거나 채운 버튼·칸 이름만 저장한다.
- 무료 기간이 끝난 계정은 AI 안내 연결을 한 번만 쓸 수 있다. 그 뒤로는 Provider 추가에서 직접 연결한다. 메일 연결 안내는 세지 않는다.

## 모델 고르기

- **대화마다 따로다.**
  - 입력창의 모델 칩이나 `/model`은 지금 대화만 바꾼다. 다음 질문부터 적용된다.
  - 새 대화는 첫 질문을 보낼 때 그 순간의 기본 모델을 자기 것으로 정한다. 나중에 기본 모델을 바꿔도 그 대화는 그대로다.
- **기본 모델**: 설정 › AI 연결 › 기본 모델 선택
- 모델 칩 메뉴
  - 열 때마다 연결된 AI들에서 목록을 새로 받는다.
  - 맨 위는 **추론 강도**다.
  - 제목 옆 **모델 검색** 칸에 이름 일부를 넣으면 연결된 모든 AI의 모델 가운데 그 글자가 든 모델만 나온다. 오른쪽에 그 모델이 있는 연결 이름이 붙는다. 칸을 비우면 원래 목록으로 돌아간다.
  - 빠른 속도를 지원하는 모델에는 ⚡ 줄이 하나 더 있다.
- **추론 강도**(`/reasoning`): 기본값, 낮음, 보통, 높음, 매우 높음. 이 대화에만 적용된다.
- **빠른 속도**(`/fast`): 지원하는 모델만 된다. 답이 빨라지는 대신 구독 사용량이 더 들 수 있다.
- 같은 모델을 구독과 API 키 둘 다로 쓸 수 있으면 구독을 먼저 쓴다.
- 연결한 AI가 없으면 모델 메뉴에 "사용할 수 있는 모델이 없습니다"가 나온다.
- 엔진이 대화를 대신해 모델을 부르는 일(조용해진 대화 정리, 파일 차례 판정, 밀린 대화 정리)은 그 대화의 모델을 쓴다.

## 이미지·동영상·웹 검색
설정 › **부가 기능 연동**에서 한다.

| 기능 | 쓸 수 있는 서비스(자동일 때 앞쪽부터) |
|---|---|
| 이미지 생성 | ChatGPT 구독 > Grok 구독 > OpenAI API 키 > xAI API 키 > OpenRouter |
| 동영상 생성 | Grok 구독 > xAI API 키 > OpenRouter |
| 웹 검색 | **기본 검색(무료)** 또는 **Brave 검색**(API 키 필요) |

- **서비스 변경**이나 **연결하기**를 누르면 서비스를 고를 수 있다. OpenRouter는 모델도 고른다. **적용**을 눌러야 바뀐다.
- 연결이 필요한 서비스는 **안내받으며 연결하기**나 API 키 칸으로 연결한다.
- 이미지·동영상 생성은 연결한 서비스가 있을 때만 에이전트가 쓸 수 있다.
  - 만든 파일은 이 PC에 저장되고 답 안에서 바로 보인다.
- 말하기(TTS)와 받아쓰기는 설정 화면이 없다. 연결한 AI에 따라 저절로 정해진다.
  - 말하기: OpenAI > Gemini > xAI API 키
  - 받아쓰기: OpenAI > Groq > xAI API 키

## 컴퓨터 조작
설정 › **부가 기능 연동** › **컴퓨터 조작** 카드에서 스위치를 켜면 에이전트가 이 PC의 화면을 보고 다른 프로그램을 직접 다룬다. 처음 설치하면 꺼져 있다. 스위치를 끄면 다음 메시지부터 쓰지 않는다.

- 에이전트가 하는 일: 화면 보기(버튼·칸에 번호를 붙인 화면과 화면의 글자 목록), 창 목록 보기·창 앞으로 가져오기, 클릭·더블클릭·오른쪽 클릭, 끌기, 스크롤, 글자 입력, 키 누르기.
  - 기본은 "뒤에서 입력"이다. 사용자의 마우스 포인터와 보고 있는 창을 빼앗지 않고 대상 창에 입력한다. 그 방식이 안 먹는 프로그램은 창을 잠깐 앞으로 가져와서 한다.
  - 화면 잠금(Win+L)과 창 닫기(Alt+F4)는 늘 막혀 있다.
- 승인: 화면 보기와 목록 보기는 묻지 않는다. 누르기·입력·창 바꾸기는 방패 칩([명령 승인](engine.md#명령-승인))을 따른다.
  - 물을 때는 답 안에 "화면을 조작해도 될까요 · 글자 입력 — 입력할 글자"(클릭, 키 누르기 등)와 **허용** / **거절**이 나온다.
  - **승인 없이 실행**이면 묻지 않고 바로 한다.
- 대화 모델이 그림을 읽지 못해도 화면의 글자 목록으로 다룰 수 있다. 그림을 읽는 모델이 더 정확하다.
- 화면을 다루는 프로그램(cua-driver, Cua의 공개 프로그램)이 Crema에 함께 설치돼 있다. 따로 설치할 것은 없다. 처음 쓸 때 Windows 보안 검사로 몇 초 늦을 수 있다.

## 웹 브라우저 조작(에고 라이트)
설정 › **부가 기능 연동** › **웹 브라우저 조작**을 켜면, 에이전트가 브라우저 **에고 라이트**(ego lite)로 사용자가 로그인해 둔 사이트에 들어가 자료를 찾고, 읽고, 칸을 채우고, 파일을 받는다.

- 에고 라이트는 Citro Labs가 만든 무료 브라우저다. Crema에 들어 있지 않고, 사용자가 처음 켤 때 설치한다.
- 처음엔 OFF다. 에고 라이트가 없을 때 스위치를 켜면 그 자리에 설치 안내와 **설치하고 켜기** · **취소**가 나온다.
- **설치하고 켜기**를 누르면 Crema가 1~2분 안에 혼자 마치고 ON이 된다. 사용자가 고르거나 누를 것은 없다.
  - 설치하는 동안 카드에 지금 단계가 보인다: 내려받는 중(몇 %) → 설치 파일 확인 → 설치 → 로그인 가져오기.
  - 에고 라이트의 공식 설치 파일을 받아 Citro Labs가 서명한 파일인지 확인한 뒤, 창 없이 이 Windows 사용자 폴더에 설치한다. 관리자 확인 창도 뜨지 않는다.
  - 에고 라이트의 첫 안내 화면은 건너뛴다. 대신 사용자의 기본 브라우저(크롬·엣지·브레이브)에서 기본 프로필의 로그인·북마크를 가져온다. 그래서 그 브라우저에서 로그인해 둔 사이트를 에고 라이트에서도 바로 쓴다.
  - 설치하는 동안 에고 라이트 창이 잠깐 떴다가 Crema가 닫는다. 설치 후의 일반 웹 작업은 숨겨진 작업 공간에서 진행한다.
  - 기본 브라우저는 바꾸지 않고, Windows를 켤 때 에고 라이트를 띄우지도 않는다. 에이전트가 쓸 때 저절로 켜진다. 바꾸고 싶으면 에고 라이트 설정에서 바꾼다.
  - 전에 에고 라이트를 설치해 쓰던 PC면 그때의 프로필과 로그인을 그대로 둔다.
  - 에고 라이트를 지우려면 Windows의 앱 설정에서 지운다. 지우면 카드가 OFF로 돌아가고, 다시 켜면 다시 설치한다.
- 설치된 뒤에는 스위치로 켜고 끈다. 끄면 에이전트가 브라우저 조작 스킬을 보지 못한다. 에고 라이트와 그 안의 로그인은 그대로 있다.
- 에이전트의 일반 웹 작업은 숨겨진 작업 공간에서 진행한다. 사용자가 이미 열어 둔 에고 라이트 창과 다른 탭은 그대로 둔다.
- 대화가 쓰던 작업 공간이 Crema 밖에서 닫혔으면(사용자가 에고 라이트에서 닫았거나 스크립트가 닫은 경우) 그 대화의 다음 웹 작업은 새 작업 공간에서 시작한다. 같은 번호에 그 대화가 만들지 않은 공간이 있으면 손대지 않고 멈춘다.
- 로그인·인증 코드·인증서·앱 승인이 필요하면 해당 작업의 정확한 페이지를 에고 라이트의 별도 정상 창으로 보여 준다. 이때부터 사용자가 조작하며, 에이전트는 페이지 조작을 멈춘다.
- 사용자가 대화에서 완료했다고 알려 주면 그 작업 창을 다시 숨기고 같은 작업 공간을 이어간다. 에이전트는 페이지를 확인해 실제로 로그인이 끝났는지 판단한다. 시간 경과나 창 닫힘만으로 완료 처리하지 않는다.
- 비밀번호와 인증 코드는 브라우저에서 직접 입력한다. 대화로 묻지 않는다. 창을 표시하거나 같은 작업을 이어받지 못하면 실패를 알리고 멈춘다.
- 보내기·올리기·제출·결제·지우기·설정 바꾸기처럼 되돌릴 수 없는 일은 에이전트가 먼저 대화로 묻는다. 읽기·찾기·내려받기는 묻지 않는다.
- 웹 브라우저 조작이 꺼져 있거나 에고 라이트가 없으면 에이전트는 로그인이 필요한 사이트 일을 하지 않고 켜 달라고 부탁한다. 사용자의 다른 브라우저를 대신 열지 않는다. 로그인이 필요 없는 공개 페이지는 웹 페이지 읽기로 읽는다. 메일 · 일정 · 파일처럼 연결된 기능이 있는 일은 그 기능으로 한다.
- 에고 라이트에 새 판이 나오면 에이전트가 알려 주고, 사용자가 허락하면 올린다.

## 메일 연결
설정 › **부가 기능 연동** › **이메일** 카드에서 한다. 연결하면 에이전트가 그 메일함에서 메일을 찾고 읽고 정리하고, 답장·전달·새 메일을 보낸다.

- 지금 연결할 수 있는 메일: **지메일(gmail.com), 네이버, 다음(daum.net·hanmail.net), 카카오**.
  - 지메일은 순서가 다르다: [구글 연결](#구글-연결지메일캘린더드라이브).
  - 아웃룩·핫메일은 아직 안 된다. 로그인만으로 연결하는 방식을 만드는 중이다.
  - 회사 메일(구글 워크스페이스 포함) 등 그 밖의 메일도 아직 안 된다.
- 연결 순서
  1. **메일 추가**를 누르고 메일 주소를 넣은 뒤 **연결 시작**을 누른다. 서버 주소는 넣지 않는다.
  2. 설정이 닫히고 대화창에 그 메일 회사의 연결 안내가 뜬다([Crema가 안내하며 연결](#crema가-안내하며-연결)). 안내가 대화창에서 묻는 대로 고르고 입력하면 Crema가 화면에 한다.
     - 그 회사 계정에 로그인한다. 2단계 인증이 꺼져 있으면 켠다(휴대폰 확인, 네이버는 네이버 앱).
     - 계정 보안에서 앱 비밀번호(애플리케이션 비밀번호)를 이름 `Crema`로 만든다. 화면에 나온 비밀번호는 Crema가 바로 가져간다. 네이버는 내정보 › 보안설정, 다음·카카오는 카카오계정 › 계정 보안.
  3. 앱 비밀번호를 받으면 Crema가 그 메일에 바로 로그인해 본다. IMAP(외부 프로그램 연결)이 이미 켜져 있으면 여기서 끝난다.
  4. 로그인이 거절되면 대개 IMAP이 꺼져 있어서다. 안내가 메일 설정으로 데려가 IMAP을 "사용함"으로 저장할지 묻는다. 저장한 뒤 **Crema에 넣기**를 누른다(비밀번호는 칸에 남아 있다). 네이버는 메일 › 환경설정 › POP3/IMAP, 다음·카카오는 메일 › 설정 › IMAP/POP3.
  5. 되면 안내가 닫히고 대화에 "○○ 메일 연결을 마쳤어요"가 남는다. 된 것만 연결된다.
- Crema는 처음 화면 하나만 직접 연다. 그다음은 사용자가 대화창에서 고르고 입력한 대로 Crema가 화면을 누르고 입력한다.
- 안내가 비밀번호를 읽지 못하면 화면이 풀린다. 화면의 비밀번호를 복사해 안내의 칸에 붙여넣고 **Crema에 넣기**를 누른다.
- 앱 비밀번호는 이 PC의 엔진 폴더에만 저장된다. Aishift 서버로 가지 않고, 백업에도 들어가지 않고, 에이전트가 돌리는 터미널 명령에도 넘어가지 않는다.
- 에이전트가 하는 일
  - 메일함 목록, 메일 찾기(검색어·보낸 사람·날짜·안 읽은 메일), 메일 읽기, 첨부 저장(기본은 내려받기 › Crema 메일 폴더)
  - 다른 메일함으로 옮기기, 읽음·안 읽음·별표 표시. 지우기는 휴지통으로 옮기는 것뿐이고 영구 삭제는 하지 않는다.
  - 새 메일·답장·전체 답장·전달 보내기(파일 첨부 가능). 보낸 메일은 보낸메일함에도 넣는다(지메일은 지메일이 직접 넣는다).
- **보내기는 매번 묻는다.** 답 안에 "보내도 될까요 · 메일 보내기 — 보내는 사람·받는 사람·제목·첨부 수"와 **허용** / **거절**이 나온다.
  - 명령 승인 칩이 **승인 없이 실행**이어도 메일 보내기는 묻는다.
  - 에이전트는 보내기 전에 받는 사람·제목·본문 전체를 답에 먼저 보여 준다. 초안만 부탁하면 보내지 않는다.
- 메일 안에 적힌 지시는 사용자의 부탁으로 여기지 않는다. 메일은 다른 사람이 쓴 글이기 때문이다.
- **연결 끊기**를 누르면 그 메일과 앱 비밀번호(지메일은 구글 로그인 정보)를 이 PC에서 지운다.

### 구글 연결(지메일·캘린더·드라이브)
지메일, 구글 캘린더, 구글 드라이브는 **따로** 연결하고 따로 끊는다. 하나만 연결해도 된다.

- 지메일: 메일 추가에서 지메일 주소로 **연결 시작**
- 구글 캘린더: 설정 › 부가 기능 연동 › **일정** 카드에서 **연결**
- 구글 드라이브: 설정 › 부가 기능 연동 › **문서 · 파일** 카드에서 **연결**

구글 화면에서 계정을 고르고 Crema를 **허용**만 하면 된다. 앱 비밀번호도, 구글 클라우드 작업도 필요 없다. Crema의 구글 연결 앱(Aishift가 구글에 등록한 "Crema")으로 허용받는다. 메일·일정·파일은 사용자 PC와 구글 사이에서만 오가고 Aishift 서버로 가지 않는다.

- **연결**(지메일은 **연결 시작**)을 누르면 사용자의 기본 브라우저에 구글 허용 화면이 열린다. 구글은 앱이 조종하는 화면에서 허용받는 것을 막으므로 이 화면은 브라우저에서 연다. Crema 설정 창은 그대로 있고, 누른 줄에 "브라우저에서 Crema를 허용해 주세요"와 **취소**가 나온 채 기다린다. 대화 화면으로 넘어가지 않는다.
  1. 브라우저에서 구글 계정 고르기(지메일은 넣은 주소의 계정)
  2. "Google에서 확인하지 않은 앱" 경고가 나오면 **고급** → **Crema(으)로 이동**. 구글의 앱 심사가 끝나기 전에는 이 경고가 나온다. 정상이다.
  3. 연결하는 기능의 권한 체크, **계속**
  4. 브라우저에 "구글 연결을 마쳤습니다"가 나오고, 설정의 그 줄이 **연결됨**으로 바뀌며 "지메일(구글 캘린더, 구글 드라이브) 연결을 마쳤습니다."가 나온다.
- 허용하지 않았거나, 권한 체크를 뺐거나, 다른 계정으로 허용하면 연결되지 않고 그 줄 아래에 이유가 나온다. 다시 **연결**을 누른다(지메일은 주소가 칸에 남아 있어 **연결 시작**만 누르면 된다).
- 브라우저 창을 닫았거나 찾지 못하면 그 줄의 **취소**를 누르고 **연결**을 다시 누른다.
- 허락하는 권한: 지메일은 메일 읽기·정리·보내기(메일을 영구히 지우는 권한은 받지 않는다), 캘린더는 일정 보기·수정과 캘린더 목록 보기, 드라이브는 파일 보기·내려받기와 Crema가 올린 파일. 캘린더 공유, 드라이브 파일 지우기·공유 권한은 받지 않는다.
- 두 번째 기능도 같은 계정으로 **연결** → 허용만 하면 된다.
- 다른 구글 계정으로 허용하면 연결되지 않는다. 지메일은 넣은 주소의 계정으로, 캘린더·드라이브는 전에 Crema에 연결한 구글 계정으로 허용한다.
- 끊기는 기능마다 한다. 지메일을 끊어도 캘린더·드라이브는 남는다. 모두 끊으면 구글에 Crema 허용 해지를 요청하고, 구글 로그인 정보도 이 PC에서 지운다. 인터넷이 끊겨 해지 요청을 못 보내면 연결 끊기가 실패하니 다시 누른다.
- 구글 로그인 정보(갱신 토큰)는 이 PC의 엔진 폴더에만 저장된다. Windows 사용자 보호 기능으로 암호화해, 이 PC의 그 Windows 사용자만 풀 수 있다. 백업에 들어가지 않고 터미널 명령에도 넘어가지 않는다.
- 이 판보다 먼저 구글을 연결했다면 에이전트가 "connect it again"이라고 한다. 그 기능을 **연결 끊기** 뒤 다시 **연결**한다.
- 에이전트가 하는 일
  - 메일(지메일을 연결했을 때): 위 [메일 연결](#메일-연결)과 같다.
  - 캘린더(구글 캘린더를 연결했을 때): 캘린더 목록, 기간·검색어로 일정 찾기, 일정 만들기·고치기·지우기. 지운 일정은 구글 캘린더 휴지통에 30일 남는다.
    - **참석자가 있는 일정**을 만들거나 고치거나 지우면 참석자에게 초대·변경·취소 알림이 간다. 그래서 메일 보내기처럼 매번 "보내도 될까요 · 일정 초대 보내기(일정 변경 알리기, 일정 취소 알리기)"로 묻는다.
  - 드라이브(구글 드라이브를 연결했을 때): 파일 찾기, 읽기(구글 문서·프레젠테이션은 글로, 시트는 CSV로), 내려받기(기본은 내려받기 › Crema 드라이브 폴더, 구글 문서는 .docx·.xlsx·.pptx로), 이 PC의 파일 올리기. 지우기와 공유는 하지 않는다.

## 업무 서비스 연결
설정 › **부가 기능 연동**의 영역 카드에서 한다. 서비스는 화면에 한글 이름으로 나온다. 연결하면 에이전트가 그 서비스의 자료를 찾고 읽고 고친다.

| 카드 | 서비스(화면 이름) | 에이전트가 하는 일 |
|---|---|---|
| 일정 | Calendly(캘린들리) | 예약 링크와 잡힌 일정을 본다 |
| 문서 · 파일 | Notion(노션) | 페이지·데이터베이스를 찾고 읽고 쓴다 |
| 문서 · 파일 | Dropbox(드롭박스) | 파일을 찾고 읽고 정리한다 |
| 할 일 · 프로젝트 관리 | Jira·Confluence(지라 · 컨플루언스) | 이슈와 문서를 찾고 고친다 |
| 할 일 · 프로젝트 관리 | Linear(리니어) | 이슈와 프로젝트를 찾고 만들고 고친다 |
| 할 일 · 프로젝트 관리 | Todoist(투두이스트) | 할 일과 프로젝트를 관리한다 |
| 디자인 · 화이트보드 | Canva(캔바) | 디자인을 찾고 만든다 |
| 디자인 · 화이트보드 | Miro(미로) | 보드와 다이어그램을 읽고 고친다 |

구글 캘린더(일정 카드)와 구글 드라이브(문서 · 파일 카드)는 같은 카드에 있지만 연결 방식이 다르다: [구글 연결](#구글-연결지메일캘린더드라이브).

- **연결**을 누르면 브라우저에 그 서비스의 로그인 화면이 열린다.
  - 로그인하고 허용하면 Crema 화면이 "연결됨"으로 바뀐다. Crema를 다시 켤 필요 없이 다음 메시지부터 쓸 수 있다.
  - 브라우저에는 "로그인했습니다" 화면과 **Crema 열기** 버튼이 나온다. 누르면 Crema 창이 앞으로 나온다(그사이 Crema를 닫았으면 켠다. 브라우저가 열지 물으면 **열기**). 그 탭은 닫아도 된다.
  - 로그인 화면에 나오는 앱 이름은 "Crema"다. 미리 만들거나 넣을 키는 없다.
  - 한 번에 한 서비스씩 연결한다. 로그인하는 동안에는 **취소**로 그만둘 수 있다.
- **연결 끊기**를 누르면 에이전트가 그 서비스를 더 쓰지 않고, 로그인 정보도 이 PC에서 지운다.
- 로그인 정보는 이 PC의 엔진 폴더에만 있다. Aishift 서버로 가지 않는다.
- 로그인한 계정이 그 서비스에서 할 수 있는 일은 에이전트도 할 수 있다(명령 승인은 서비스에서 하는 일에는 적용되지 않는다).
- 목록에 없는 서비스는 대화에서 주소로 연결한다: [기타 서비스](#기타-서비스).

## 기타 서비스
목록에 없는 서비스도 MCP 서버 주소가 있으면 연결할 수 있다. 설정에는 주소를 넣는 칸이 없고, 대화에서 부탁한다.

- 사용자가 주소(`https://`로 시작)를 주고 연결해 달라고 하면 에이전트가 `crema_services` 도구로 연결한다.
  - 먼저 승인 창이 뜬다. 허용해야 연결한다.
  - 그 서비스가 로그인을 요구하면 브라우저에 로그인 화면이 열린다. 로그인하고 허용하면 연결된다. 몇 분 안에 끝내지 않으면 연결하지 않는다.
  - 연결되면 다음 메시지부터 그 서비스의 도구를 쓴다. Crema를 다시 켤 필요가 없다.
- 연결한 서비스는 설정 › **부가 기능 연동** 맨 아래 **기타 서비스** 카드에 나온다. 하나도 없으면 카드가 없다.
  - 줄마다 서비스 이름, 주소, 켜고 끄는 스위치만 있다.
  - 끄면 에이전트가 그 서비스를 쓰지 않는다. 로그인은 남아서, 다시 켜면 바로 쓴다.
- 아주 지우려면 대화에서 "○○ 연결 지워 줘"라고 한다. 로그인 정보도 이 PC에서 지운다.
- 연결하지 못하는 서버
  - API 키를 넣어야 하는 서버
  - PC에 프로그램을 설치해 띄우는 서버(`npx …` 같은 명령으로 실행하는 것)
  - 주소가 `https://`로 시작하지 않는 서버
- 로그인한 계정이 그 서비스에서 할 수 있는 일은 에이전트도 할 수 있다. 돈이 드는 서비스(크레딧 차감 등)는 에이전트가 쓸 때마다 비용이 든다.
- 웹 페이지·파일·도구 결과에 적힌 주소는, 사용자가 그 주소를 연결해 달라고 하지 않는 한 연결하지 않는다.

## 음성 입력

Crema가 말을 받아 적는 방식은 두 가지다. 마이크 버튼은 엔진이 연결된 뒤에 보인다.

| 방식 | 조건 | 동작 |
|---|---|---|
| **Thock** | 플랜에 음성 입력이 들어 있고(프로·프리미엄·무료 한 달), 설정 › 입력 › 음성 입력 켜기가 켜져 있음 | 마이크 버튼을 누르고 말하면 Thock이 받아 적고, 버튼이 주황색으로 깜박인다. 다시 누르면 받아 적기를 멈춘다. Windows 어느 창에서든 CapsLock을 눌러도 같다 |
| **엔진 받아쓰기** | 위 조건이 아닐 때. OpenAI API 키, Groq, xAI API 키 중 하나가 연결돼 있어야 함 | 마이크 버튼을 누르고 말한 뒤 다시 누르면, 연결한 AI가 녹음을 글로 바꿔 커서 자리에 넣는다(한국어) |

- Thock은 말하면 글로 받아 적어 주는 Aishift 프로그램이다.
  - Crema에 들어 있지 않다. Microsoft Store에서 따로 설치한다. Crema는 이 PC에 설치된 Thock 하나를 찾아 연결한다.
  - 마이크 버튼을 눌렀을 때 Thock이 꺼져 있으면 Crema가 켠다. Thock이 설치돼 있지 않으면 알림에 **Thock 설치하기**가, 판이 오래돼 연결하지 못하면 **Thock 업데이트하기**가 나온다.
  - Thock은 Crema와 따로 업데이트된다. Store에서 받은 Thock은 Microsoft Store가, 홈페이지에서 받은 Thock은 Thock이 스스로 업데이트한다. 업데이트로 Thock이 다시 켜지면 Crema가 1분 안에 다시 연결한다.
  - Crema가 연결돼 있는 동안 Thock의 설정 창과 첫 실행 안내는 Crema 창으로 열린다. Crema를 닫거나 음성 입력을 끄면 연결만 끊긴다. Thock은 꺼지지 않고 혼자 쓰는 Thock으로 돌아간다.
  - Thock이 로그인 전이면 Crema의 로그인을 넘겨받는다. 같은 Aishift 계정이라 Crema 플랜에 든 음성 입력을 Thock도 그대로 쓴다.
- 받아쓴 말이 소리가 비슷한 다른 말로 적힌 것을 AI가 대화 맥락으로 알아채면, 그 짝(적힌 말 → 맞는 말)을 Thock에 알린다.
  - Thock은 그 말이 최근 30분 안의 받아쓰기에 있을 때만 센다. 직접 친 말은 배우지 않는다.
  - 같은 짝이 두 번 오면 확정되어 다음 받아쓰기부터 맞게 적는다. 직접 고쳐서 배우는 것과 같다.
  - Thock이 배운 짝은 Thock 설정의 **내가 고친 단어 목록**에서 보고 지울 수 있다. Thock 설정에서 **자동으로 배우기**를 끄면 Thock은 이런 짝을 배우지 않는다.
- Thock 설정(단축키, 마이크, 시작 키워드 등록, 내 목소리 등록 등)은 설정 › 입력 › **음성 입력 설정 열기**에서 본다. Thock 창으로 열린다.
- 등록한 내 목소리와 시작 키워드, Thock이 배운 단어, 설정값은 Thock 자료 폴더(`%USERPROFILE%\.voicetype`)에 있다. Crema가 연결돼 있든 아니든 같은 자료를 쓴다.
- Thock을 이 PC에서 처음 쓰면 Thock 첫 실행 안내가 뜬다(마이크 확인 → 단축키 → 말로 하는 명령 정하기(시작 키워드와 내 목소리 등록) → 사용법). Crema가 Thock을 켜서 연결했어도 안내는 Thock 창으로 뜨고, 로그인은 Crema가 하므로 계정 단계는 없다.
- 음성 오류: [troubleshooting.md](troubleshooting.md#음성-입력)
