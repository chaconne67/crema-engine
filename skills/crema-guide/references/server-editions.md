# 서버판: Krema와 Jabis

Crema에는 PC에 설치해 혼자 쓰는 판 말고, 회사 서버에서 도는 판이 둘 있다. 이 설명서의 다른 파일은 PC판 이야기다. 서버판에서 일하고 있다면 이 파일이 먼저다.

| 이름 | 주소 | 누가 쓰는가 |
|---|---|---|
| Krema | `krema.cloud` | 회사의 개발자와 직원 |
| Jabis | `jabis.cloud` | 보험 설계사(FC). 고객을 챙기는 비서 |

## PC판과 다른 점
- 에이전트(엔진)가 사용자 PC가 아니라 서버에서 돈다. 대화도 서버에 저장되어, 같은 계정으로 들어온 모든 기기(브라우저, 휴대폰 홈 화면 앱, PC 앱)에 같은 대화가 보인다.
- 화면의 이름은 Crema가 아니라 Krema 또는 Jabis다. 사용자에게 말할 때 그 이름을 쓴다.
- 로그인은 Google 계정으로 한다. Krema에서는 **Google로 시작하기**를 누른다. Krema 이용 권한은 운영자(Aishift)가 준다. 권한이 없는 계정을 골랐다면 **다른 계정으로 로그인**에서 다시 시작한다.
- Jabis 소개 화면에서는 **구글로 시작하기**를 누른다. 첫 로그인, 체험, 이용 문의는 [Jabis 가입·체험·해지](#jabis-가입체험해지)를 참고한다.
- 로그아웃은 설정 › 계정의 **로그아웃**이다. 대화 기록은 지워지지 않는다.

## 첫 실행과 첫 만남

- 새 계정은 엔진에 처음 접속할 때 **에이전트 설정**에서 비서의 이름, 나를 부를 호칭, 존댓말·반말, 바라는 점을 고를 수 있다. **시작하기**로 저장하거나 **건너뛰기**를 누른다. 이미 자기 지침을 갖고 있는 계정은 기존 설정으로 시작한다. 저장한 내용은 설정 › **지침**에서 확인한다.

### 첫 만남과 브리핑
- 처음 로그인하면 왼쪽 대화 목록 위의 고정 비서 대화에서 비서가 먼저 인사하고 호칭, 말투, 브리핑 시각, 먼저 제안하는 정도를 함께 정한다. 질문 상자에서 고르거나 대화로 답한다. 건너뛰면 오전 9시 브리핑과 먼저 제안 켬으로 시작한다.
- 정한 값은 계정에 저장된다. 다른 기기와 다음 대화, 다음 브리핑에서도 쓰이며 대화로 바꿀 수 있다.
- Jabis는 금융 소식지를 받을지, 주기(기본 매월), 받을 고객도 묻는다. 고객 명단 파일 올리기와 PC 앱 받기, PC에서 카톡 보내기 켜기를 안내한다. 나중에 하겠다고 하면 넘어가고 다음 브리핑에서 다시 권한다. 소식지 설정은 발송 승인이 아니다.
- 정한 시각에 같은 비서 대화에 브리핑이 쌓인다. 그 자리에서 답하면 비서와 이어서 이야기한다. 이 대화는 왼쪽 목록 위에 정해진 자리에서 열며 삭제할 수 없다. 기존 **첫 만남**과 날짜별 **오늘** 대화의 기록과 승인 카드는 비서 대화에서 이어서 볼 수 있다. 중요한 것 다섯 건을 먼저 보고 나머지는 **더 보기**로 연다.
- 챙길 일이 없으면 알림 없이 한 줄만 남긴다. 밤 9시부터 오전 7시까지는 조용하며, 같은 날 다시 실행해도 같은 브리핑이나 알림을 두 번 쌓지 않는다. 화면을 하나라도 보고 있으면 어느 기기에도 알리지 않는다.
- 질문이나 발송 승인을 기다리는 대화는 왼쪽 목록에 **확인을 기다립니다** 표시가 난다. 그 대화를 열어 질문이나 확인 상자에 답하면 표시가 사라진다.

## 계정 등급마다 보이는 것
계정에는 등급이 있고, 등급에 없는 기능은 화면에 아예 나오지 않는다. 사용자가 고르거나 켤 수 있는 것이 아니다.

| 기능 | 개발자 (Krema) | 직원 (Krema) | FC (Jabis) |
|---|---|---|---|
| 대화, 파일 첨부, 알림 | 있음 | 있음 | 있음 |
| 프로젝트 | 있음 | 있음 | 있음 |
| 스킬 | 있음 | 있음 | 없음 |
| 모델 고르기(추론 강도·빠른 속도 포함) | 있음 | 없음 | 없음 |
| 사용량 보기(입력창의 고리, `/usage`) | 있음 | 없음 | 없음 |
| 상태 보기(`/status`) | 연결·세션·모델·사용량 | 연결·세션 | 연결·세션 |
| 자기 서버 폴더 또는 연결한 PC로 프로젝트 폴더 바꾸기 | 있음 | 있음 | 있음 |
| 권한 있는 공유 서버 폴더를 프로젝트로 붙이기 | 있음 | 없음 | 없음 |
| 오류 정보 보내기 설정과 변경 원칙 | 있음 | 없음 | 없음 |

## 프로젝트 폴더

- 프로젝트 메뉴에서 **프로젝트 편집 › 폴더 위치 › 변경**을 누른다. 자기 서버 폴더나 계정에 연결된 PC의 폴더를 고르고 **저장**한다. 개발자는 접근 권한이 있는 공유 서버 폴더도 고를 수 있다. 프로젝트의 대화는 유지되고 다음 요청부터 새 폴더를 쓴다.
- 같은 프로젝트에서 답이 진행 중이면 끝난 뒤 폴더를 바꾼다. PC 폴더를 고르면 연결된 PC에서 원본 경로를 확인한다. PC가 연결되어 있어야 **탐색기로 열기**를 쓸 수 있다. 실행 파일 링크는 탐색기에서 파일의 위치를 보여 준다.
- 프로젝트 메뉴의 **프로젝트 폴더 지우기**는 확인창을 거친 뒤 서버의 폴더와 그 안의 파일, 이전 상태, 그 프로젝트의 대화 기록을 영구 삭제한다. 되돌릴 수 없다. PC판의 프로젝트 제거와 다르다.
- 직원과 FC에게 프로젝트 기능이 열려 있을 때는 자기 공간 안의 폴더만 지운다. 개발자는 프로젝트로 고른 서버 폴더도 지운다.
- FC도 자기 공간에서 프로젝트를 만들고, 선택하고, 삭제할 수 있다. 직원과 FC의 프로젝트는 각자 자기 공간 안에 있다.
- 직원과 FC의 파일 도구는 계정 프로필의 `file_access_roots` 설정으로 자기 작업 공간, 올린 파일, 자기 캐시 안에 제한된다. 다른 계정 공간과 서버의 나머지 파일은 읽거나 고치거나 검색할 수 없다. 개발자 프로필에 이 설정이 없으면 기존 서버 파일 접근을 유지한다. 이 경계는 서비스가 계정마다 정하며 사용자가 직접 설정하지 않는다.
- 서버 자료는 개인 드라이브에 암호화해 하루 한 번 백업하고 최신 3개를 보관한다. 개인 드라이브가 연결되지 않았으면 회사 드라이브를 사용한다. 백업에 실패하면 본인과 관리자에게 자료 보관 관련 대화와 알림이 전달된다.
- 업로드 파일이나 프로젝트 목록에서 뺀 프로젝트는 성공한 백업 뒤 미참조 상태인지 확인하고 30일 유예 후 정리한다. 다시 참조된 자료와 활성 프로젝트는 보존한다.
- 파일 보기의 **이전 상태**에서 **이때로 되돌리기**를 누르면 그때의 파일 상태로 돌아간다. 되돌리기 직전 상태도 기록에 남는다.
- 같은 프로젝트의 어느 대화든 답을 쓰고 있으면 이전 상태로 되돌리기와 폴더 지우기를 막고 이유를 보여 준다. 다른 기기에서 쓰는 답과 프로젝트의 하위 폴더에서 쓰는 답도 포함한다. 답이 끝나면 다시 할 수 있다. 파일 목록은 계속 볼 수 있다.

## 모델
- 개발자 계정만 모델을 고른다. 방법은 PC판과 같다(입력창의 모델 칩, `/model`).
- 직원과 FC 계정은 서버가 정한 모델로 답한다. 모델 이름과 토큰 사용량은 개발자 계정에서 확인할 수 있다. 입력창에 모델 칩과 사용량 고리가 없고, 명령 메뉴에 `/model`, `/reasoning`, `/fast`, `/usage`가 없다.
  - 이 계정의 사용자가 모델을 바꾸고 싶다고 하면 "이 계정에서는 모델을 고를 수 없다"고 답한다. PC판의 방법(모델 칩, 설정 › AI 연결)을 안내하지 않는다.
  - 모델 이름이나 토큰 수를 먼저 꺼내지 않는다. 화면에도 나오지 않는 것이다.
- **관리자가 이 계정의 모델 배정을 고쳐야 합니다**가 보이면 관리자가 이 계정에 사용할 모델을 다시 지정해야 한다. 관리자에게 화면에 나온 문구를 전하고, 배정이 고쳐진 뒤 다시 보내라고 안내한다.
- 사용 한도에 걸리면 "AI 사용 한도에 걸렸습니다. 잠시 뒤 다시 보내 주세요."가 나온다. 직원과 FC에게 모델을 고르라고 안내하지 않는다.

## 대화 옆에서 묻기
- 답변의 일부를 골라 **자세히 물어보기**를 누르면 대화 옆에서 뜻을 물을 수 있다. 그 문답은 본 대화에 들어가지 않으며 파일이나 작업 결과를 바꾸지 않는다.
- 프로젝트를 고르는 단추는 서비스 이름(Krema 또는 Jabis)으로 그 폴더에서 일한다고 안내한다. 프로젝트를 고른 뒤에는 폴더 경로를 보여 준다.

## 명령 메뉴(`/`)
- 직원·FC 계정: **새 세션** `/new`, **화면 지우기** `/clear`, **다시 시도** `/retry`, **답변 멈추기** `/stop`, **대화 이름 바꾸기** `/title`, **명령어 도움말** `/help`.
- Krema와 Jabis의 **상태 보기** `/status`에서 연결, 엔진 버전, 프로젝트와 세션을 확인한다. 모델 이름과 토큰 수는 개발자의 상태 화면에 표시된다.
- 개발자 계정은 **모델 선택** `/model`, **추론 강도** `/reasoning`, **빠른 속도** `/fast`, **사용량 보기** `/usage`도 쓴다.

## 하트비트

Krema와 Jabis에서는 모든 계정이 하트비트를 쓸 수 있다. 처음에는 꺼져 있다.

- 기록이 있는 대화에서 `/heartbeat every 30m 진행 중인 일의 바뀐 점을 알려 줘`처럼 입력한다. `30m`은 30분이다. 가장 짧은 간격은 1분이다.
- 상태는 `/heartbeat`로 본다. `/heartbeat pause`로 멈추고 `/heartbeat resume`으로 같은 설정을 다시 시작한다. `/heartbeat off`는 설정을 지운다.
- PC 앱이나 브라우저를 닫아도 서버에서 정한 간격마다 실행할 수 있다. 실행될 때마다 모델을 사용하므로 사용량이나 요금이 발생할 수 있다. 결과는 하트비트를 켠 대화에서 본다.
- 관리자에게 모델 배정을 고쳐 달라는 안내가 오면 계정 관리자에게 알린다. Jabis를 해지하거나 체험이 끝나면 하트비트 실행이 멈춘다. 보관 기간에는 기존 대화를 계속 읽을 수 있다.

## 설정
- 모든 계정에 계정, 자기 지침, 모양, 알림, 입력 설정이 있다. 직원은 첫 접속에서 자기 엔진 공간이 준비되며 자기 지침을 고치고 비서와 대화할 수 있다.
- 세 계정 모두 설정 › **알림**에서 **알림 소리**를 기기별로 고른다.
- Krema 개발자는 설정 › **계정**에서 **오류 정보 보내기**, 설정 › **지침**에서 **변경 원칙**을 켜고 끌 수 있다. 오류 정보 보내기는 처음 켜져 있고 Krema 직원과 Jabis는 기본 수집 설정을 따른다. 변경 원칙은 처음 꺼져 있다. 켜면 변경을 시작할 때와 커밋 직전에 현재 대화의 모델로 판정하고, 확인이 필요하면 대화에 표시한다.
- Krema와 Jabis는 **예약 작업**에서 목록을 보고 예약을 멈추거나 다시 켜거나 지울 수 있다. 설정 › **입력**에서 **앞 대화 요약 시점**을 바꾼다.
- Krema 개발자와 직원은 입력창의 방패 아이콘에서 **승인 요청** 또는 **승인 없이 실행**을 고른다. Jabis는 계정의 서버 작업 권한으로 실행 여부를 정한다.
- 개발자는 **AI 연결**에서 모델 공급자 연결을 추가한다. 오픈소스 고지 링크는 두 Krema 등급의 계정 설정에 있다.
- 지침에서 자기 성격·말투(SOUL.md)와 일하는 규칙(CREMA.md)을 저장한다. 다음 새 대화부터 적용되며 서버를 다시 켜도 남는다. Krema 개발자만 서비스 공통 지침을 편집한다. 저장한 공통 지침은 서버를 업데이트한 뒤에도 기존 계정과 새 계정의 대화에 적용된다.
- 부가 기능 연동에서 이메일, 일정, 문서 · 파일과 업무 서비스를 연결한다. PC 앱에는 그 PC의 카톡 보내기와 웹 브라우저 조작도 있다. Krema와 Jabis의 **웹 검색** 카드에는 AI 기본 검색과 네이버 검색이 표시된다. 대화에서 네이버로 찾아 달라고 하면 된다.

- 설정 › **부가 기능 연동 › 말하기**에서 구독 음성의 연결 상태를 확인한다. 지원되는 구독이 연결되면 대화에서 소리 내어 읽어 달라고 할 수 있다. 지금은 연결 안내가 표시된다. 서버판 말하기는 구독 연결만 쓴다.

## PC 앱으로 연결 안내 열기

- Krema 개발자는 설정 › **AI 연결**에서 AI 공급자의 연결 안내를 열 수 있다. Krema 개발자·직원과 Jabis는 **부가 기능 연동 › 이메일**에서 네이버·다음·카카오 메일 연결 안내를 연다.
- 같은 계정의 PC 앱이 켜져 있으면 PC에 안내 창이 열린다. 연결된 PC가 여러 대면 창을 띄울 PC를 고른다. 공급자 로그인, 동의, 비밀번호와 API 키 입력은 사용자가 한다. 서비스 설정에 입력한 연결 정보는 서버의 자기 계정 공간에 저장된다.
- **PC 앱을 켜 주세요**가 보이면 PC 앱을 켜서 다시 열거나 현재 설정 화면에서 **직접 연결**을 고른다. PC 창이 직접 연결 방법을 보여 주면 그 안내에 따라 서비스 설정에서 마친다.

## 메일 · 일정 · 드라이브와 업무 서비스
- Google 연결은 서비스 로그인과 별개다. 처음 한 번 그 사람의 Google 계정에 개인 연결 앱을 준비한다. 회사 공용 앱이나 구글 심사를 안내하지 않는다.
- 사용자가 구글 연결을 시키면 비서가 PC 앱의 웹 브라우저 조작으로 처음부터 끝까지 한다. 사람에게는 Google 로그인(비밀번호, 2단계 인증)만 넘긴다. PC가 없거나 웹 브라우저 조작이 꺼져 있으면 PC 앱에서 켜고 이어 하도록 안내한다. 사용자에게 Google 콘솔 작업이나 파일 고르기를 떠넘기지 않는다.
- 개인 앱은 웹 애플리케이션으로 만들고 Gmail, Calendar, Drive API를 켠다. 동의 화면은 본인만 쓰도록 준비하고 운영 상태로 둔다. 돌아올 주소는 현재 서비스 주소 뒤에 `/engine/api/crema/google/callback`을 붙인 것이다.
- 콘솔에서 내려받은 연결 앱 JSON 파일은 비서가 `google_connect`의 app으로 그 계정에 넣는다. 파일 내용은 서버로만 가고 대화에 나오지 않는다. 그다음 지메일, 구글 캘린더, 구글 드라이브를 하나씩 `google_connect`의 connect로 허용 화면을 열어 비서가 허용하고, status로 연결을 확인한다. 같은 개인 앱을 재사용하며 그 기능의 권한만 허용한다.
- 지메일에는 `gmail.com` 주소뿐 아니라 회사 도메인의 구글 메일(Google Workspace, 예: `이름@회사.kr`) 주소도 넣는다. 그 주소가 실제로 지메일을 쓰는지는 허용 뒤 Google이 확인하고, 지메일이 아니면 연결되지 않는다. 네이버·다음·카카오 주소는 구글 연결이 아니라 앱 비밀번호로 연결한다.
- 사용자가 직접 바꿀 때는 설정 › 부가 기능 연동 › **구글 연결 준비**의 **연결 앱 파일 선택**과 각 기능의 연결 버튼을 쓴다.
- 허용 화면을 열기 전에 사용자에게 곧 뜰 화면을 알린다. 'Google에서 확인하지 않은 앱', '안전하지 않음' 경고는 사용자가 자기 구글 계정에 직접 만든 연결 앱이라 구글 심사를 받지 않아서 뜬다. 자료는 사용자의 구글 계정과 이 서비스 사이에서만 오간다. 일반 사용자는 이 경고에 겁먹고 멈출 수 있으니, 사용자가 그 화면을 직접 할 때는 이유와 함께 순서를 번호로 안내한다.
  1. 연결할 구글 계정을 고른다.
  2. 경고 화면 왼쪽 아래의 **고급**을 누른다.
  3. 아래에 나온 **(앱 이름)(으)로 이동(안전하지 않음)**을 누른다.
  4. 권한 목록의 체크 상자를 모두 체크한다. 빠진 권한이 있으면 그 기능이 동작하지 않는다.
  5. **계속**을 누른다. '구글 연결을 마쳤습니다' 화면이 뜨면 끝이다.
- 권한은 서버의 자기 칸에 남는다. 연결한 뒤에는 휴대폰에서 시켜도 서버가 메일 · 일정 · 드라이브를 쓴다. 연결 끊기는 고른 기능만 끊고, 마지막 기능을 끊으면 Google 권한도 회수한다.
- 공개된 업무 서비스 주소는 대화에서 연결을 시킬 수도 있다. 연결 승인 뒤 그 서비스의 로그인 주소를 사용자에게 보여 주고, 완료 여부를 확인한다. 연결한 서비스의 도구는 다음 메시지부터 보인다. 서버 내부 주소는 연결하지 못한다.
- 다른 대화에 일을 맡기거나 말을 전하는 기능은 같은 계정의 대화끼리만 된다. 사용자는 다른 대화의 메시지와 답을 그 대화에서 볼 수 있다.

## 대화에서 화면으로 고르기

- Krema 개발자·직원과 Jabis 사용자는 목록을 화면으로 보여 달라고 할 수 있다. 답 아래에 열린 화면에서 항목을 고르고 **확인**을 누르면 앱이 선택 내용을 같은 대화에 메시지로 보낸다.

## Jabis의 대화와 개인 예약에서 할 수 있는 일

- Jabis 비서는 대화와 개인 예약에서 지난 대화를 검색하고, 다시 쓸 정보를 모아 두는 지식 노트를 찾아 읽거나 정리할 수 있다. 자기 프로젝트 폴더와 올린 파일을 다루고, 웹을 검색하거나 페이지 본문을 읽을 수 있다. 사용자의 선택이 필요하면 대화에서 물어볼 수 있다.

## 스킬
- Krema 개발자와 직원은 설정 › 스킬에서 공통, 직접 만든, 설치한, 배운 스킬을 구분해 볼 수 있다. 대화에서 만들기·고치기·지우기·주소로 설치를 시켜도 된다.
- 기본 스킬은 계정에 처음부터 들어 있다. 추가로 설치할 수 있는 스킬은 계정의 등급에 따라 다르다. Jabis와 Krema의 대화에서 “설치할 수 있는 스킬을 알려 줘”라고 물으면 이름과 용도를 볼 수 있다.
- “영상 제작 스킬 설치해 줘”라고 말하면 비서가 목록을 확인하고 내 계정에 설치한다. 설치한 스킬은 다음 대화에서도 쓸 수 있다. 같은 이름의 스킬이 있으면 기존 사본이 그대로 남는다. “영상 제작 스킬 지워 줘”라고 말하면 설치한 사본을 지울 수 있다.
- 공통 원본은 읽기 전용이다. 내 사본으로 수정해 저장하면 자기 공간의 사본을 먼저 쓴다. 내 사본 삭제로 공통 스킬로 돌아간다. 제품 설명서는 설치된 엔진 판을 따른다.
- 외부 주소에서 받은 스킬은 위험 검사를 거친다. 직원은 검사를 통과한 스킬을 설치할 수 있다. 위험 판정이 나오면 직원에게는 거절 안내가 표시된다. 개발자는 검사 결과를 보고 **그래도 설치**를 고를 수 있다. FC는 설치 가능 목록에서 대화로 설치한다.
- 직원은 `/` 메뉴에서 메일·일정, 한국어 윤문 등 계정에 있는 스킬을 고를 수 있다. 발표 자료 PDF 스킬은 대화로 설치할 수 있다. 발표 PDF는 서버에서 만들고, 메일과 일정은 자기 연결을 쓴다. PC의 웹 작업은 `pc_browser`로 한다.
- Jabis에서 스킬을 만들거나 고치려면 대화에서 어떤 일을 어떻게 처리할지 말한다. 설치할 때는 설치 가능 목록에서 고른다.

## 개인 예약

- Krema 개발자·직원과 Jabis는 대화에서 개인 예약을 만들 수 있다. 시각이 되면 예약을 만든 대화의 문맥과 현재 프로젝트를 쓰고, 요청과 결과가 같은 대화에 남는다.
- 예약은 그 계정의 대화에서 허용된 도구를 쓴다. PC 일은 권한이 켜진 연결 PC가 맡는다. 사용할 PC가 꺼져 있거나 작업을 받을 수 없으면 같은 대화에 맡지 못한 사유가 남는다.
- 두 Krema 등급에서 PC용 Crema 자료를 가져오면 예약이 일시정지 상태로 들어온다. 같은 예약은 한쪽에서만 실행되도록 원래 PC의 예약을 확인한 뒤 다시 켠다.

## 관리와 자료 보관
- 계정과 등급의 모델·구독·API 키, 월 예상 비용 알림은 계정 서버 관리 화면에서 운영자가 정한다. 비어 있는 계정은 서비스 기본 구독 모델을 따른다. 직원은 모델과 제공자·옵션을 바꿀 수 없다.
- 사용량 표에는 입력·출력 토큰, 예상 비용(USD), 자료량과 수집 시각이 보인다. 구독 모델의 예상 비용은 실제 구독 청구액과 다를 수 있다. 알림 금액이 비어 있으면 운영자에게 한 번 알린다.
- 매일 암호화 백업은 개인 Google 드라이브에 최신 세 개를 보관한다. Google을 연결하지 않은 사람의 자료와 서비스 DB는 회사 드라이브에 보관한다. 연결 끊김이나 용량 부족으로 백업하지 못하면 본인과 운영자에게 알린다. 서버의 예약 설치와 실제 Google 연결 확인이 끝난 뒤 동작한다.
- 대화와 프로젝트 목록에서 참조가 끊긴 자료는 백업이 성공한 뒤 30일 유예를 두고 정리한다. 작업 중인 프로젝트와 다시 참조한 자료는 보존한다.
- FC도 자기 공간에서 프로젝트 폴더를 만들고, 대화의 작업 폴더로 고르고, 목록에서 제거하거나 자기 폴더를 삭제할 수 있다.

### 내 자료 ZIP

- Krema 개발자·직원과 Jabis에서 대화에 “내 자료 ZIP으로 만들어 줘”라고 요청한다. 준비가 끝나면 응답의 링크로 웹이나 PC 앱에서 받는다. 링크를 만든 계정으로 로그인해야 열린다.
- ZIP에는 내보내기를 요청한 시점의 자기 계정 자료를 담는다. 링크를 다시 열면 같은 시점의 자료를 받는다.
- 직원과 FC가 받는 ZIP은 대화 내용을 담고 모델·공급자·토큰 사용량 항목을 비운다. 인증값과 비밀은 모든 계정의 ZIP에서 제외한다.

## 서버에서 하는 정리
- 창을 닫아도 서버는 조용해진 대화를 정리한다. 새 질문이 오면 같은 사용자의 정리를 중단하고 답변을 우선한다.
- 기록하거나 배운 것이 있으면 해당 대화의 답 아래 기록에 나타난다. 다시 열어도 중복되지 않으며 취소 버튼으로 되돌릴 수 있다.
- 노트의 하루 정리 기록은 서버에 남는다. 지난 대화의 한글 검색과 노트의 뜻 검색도 서버에서 한다. 같은 계정의 두 대화가 같은 파일을 고칠 때 차례를 지키고, 답 아래에는 만든 파일 목록이 보인다.
- 각 계정의 지침, 스킬, 노트와 파일 차례 장부는 다른 계정과 섞지 않는다.

## 고객 관리와 녹음
- 개발자·직원·FC가 같은 고객 자료 도구와 업종 스킬을 쓴다. 자료는 계정별로 분리된다. 스킬 메뉴가 없는 FC도 대화에서 업종 스킬을 쓸 수 있고, 외부 스킬 설치는 거절된다.
- 명단 파일을 대화에 올리고 고객으로 정리해 달라고 말한다. 같은 사람인지 불분명하면 비서가 묻는다. 카톡의 **대화 내보내기**로 만든 .txt는 누구의 상담인지 알려 주면 그 고객의 상담 이력에 원문 그대로 붙인다.
- 녹음을 올리면 비서가 서버에서 글로 옮긴다. 누구와의 녹음인지 오늘 대화에서 고객을 고른 뒤 요약·확인할 정보·할 일 제안을 받는다. 원음은 글로 옮긴 즉시 지우고 글과 고객 기록은 남긴다. 같은 녹음을 다시 올려도 중복 제안하지 않는다.
- 서버 자료를 되살린 뒤 받아쓰지 않은 녹음은 휴대폰의 Thock에서 원본을 다시 올린다. 이미 정리한 녹음과 고객 기록은 그대로 이어 쓴다.
- 화자를 구분하지 못한 녹음에서 추린 정보는 확인 필요로 표시한다. 맞는 정보만 고르면 확인 상태가 된다. 확인하지 않은 정보를 근거로 하는 고객 발송은 거절된다. 할 일은 등록할 것을 골라 확정한다. 1분 미만이거나 약속만 잡은 통화는 통화 기록만 남긴다.
- 고객에게 보내라고 하면 비서가 글을 준비하고 제품의 확인 상자를 띄운다. PC에서 카톡 보내기를 켜 둔 사용자가 직접 승인해야 보낸다. 보냈는지 불명확한 건은 다시 보내지 않고 카톡에서 확인한다.
- 자기 지침은 설정의 지침에서 고친다. 업종 스킬과 말투·브리핑은 같은 계정의 새 대화와 예약에도 적용된다.

## 그림에 주석 달고 묻기
- 입력창에 캡처나 스캔 그림을 첨부한 뒤 그림 옆 **주석 달기**를 누른다. PDF 한 쪽도 그림으로 첨부한다.
- 그림에서 범위를 끌어 선택하면 번호와 그 범위의 대화창이 생긴다. **숫자로 범위 선택**을 펼쳐 위치와 크기를 적어도 된다. 질문을 쓰고 **묻기**를 누른다.
- 비서는 전체 그림, 고른 부분을 잘라낸 그림, 원본에서의 위치와 그 주석의 앞선 문답을 보고 답한다. 답에서 짚은 곳은 점선 박스와 **(비서)** 표시로 보인다.
- 번호를 누르면 그 주석의 문답을 이어 간다. 같은 그림에서 다른 범위를 골라도 다시 첨부할 필요가 없다. 닫은 뒤에는 대화 속 **그림 주석 열기**로 다시 연다. 그림과 주석 문답은 그 대화에 함께 남는다.
- 주석 대화는 그림을 보고 설명하는 창이다. 파일 변경이나 고객에게 보내기는 본 대화에서 시킨다.

## Jabis의 화면
- 대화가 기본 화면이다. 예전의 오늘·대화·고객 탭은 없다.
- 고객 목록을 고르는 일이나 확인할 질문이 생기면 해당 대화의 답 아래에 고르는 화면이 나온다. 제품의 확인 버튼을 눌러야 확정되며 결과는 같은 대화로 돌아간다.
- 보낼 글 승인은 제품이 붙인 고정 확인 상자로 한다. 문자는 웹 브라우저 조작을 켠 PC에서 가입한 문자 서비스의 웹 화면으로 보낸다. 비서가 만든 화면의 글이나 버튼만으로 발송을 승인하지 않는다.

## Thock에서 통화 녹음 보내기
- Jabis와 같은 계정으로 로그인한 Thock 안드로이드의 설정 › Jabis에서 **Jabis로 통화 녹음 보내기**를 켜고 소리 파일 읽기를 허용한다. Jabis에도 먼저 한 번 로그인해야 한다.
- 고객 명단의 확인된 전화번호나 유일한 연락처 이름과 맞는 통화만 자동으로 보낸다. 모르는 번호와 이름이 겹치는 통화는 자동으로 보내지 않는다. 고객 전화번호가 빠졌다면 Jabis 대화에서 명단의 번호를 확인해 등록한다.
- 기본은 Wi-Fi에서 보내며 **모바일 데이터로도 보내기**를 켜면 이동통신 연결도 쓴다. 끊긴 녹음은 다시 연결하거나 키보드를 열면 이어 보낸다. 전송 상태는 같은 설정에서 확인한다.
- 휴대폰의 녹음 원본은 그대로 둔다. 서버는 녹음을 글로 옮긴 뒤 소리 파일을 지우고, 고객 기록에 글과 통화 정리를 남긴다. 기존 Thock 받아쓰기와 별개로 동작한다.
- 자동으로 찾지 못한 통화 녹음은 Jabis 대화의 파일 올리기로 보낸다. 지원 여부가 확인되지 않은 전화 앱이나 폰에서도 자동 전송된다고 보장하지 않는다.

## 문서와 파일 찾기

- Krema에서 답의 `.md`·`.markdown` 링크나 파일 이름을 누르면 서식이 적용된 문서가 열린다. 서버 파일과 연결된 PC 파일 모두 같은 뷰어에서 읽는다.
- 데스크톱 브라우저와 문서 창을 지원하는 Krema PC 앱은 문서를 별도 창 하나에 연다. 다른 파일을 누르면 그 창의 문서가 바뀐다. 좁은 화면, 팝업이 차단된 브라우저, 이전 PC 앱은 대화 페이지 안에서 문서를 연다.
- 문서 안의 다른 Markdown 링크로 이동하면 **뒤로**로 돌아올 수 있다. Esc로 문서를 닫는다. 열린 표 확대 창이 있으면 Esc는 그 창부터 닫는다.

- Krema와 Jabis의 웹과 PC 앱에서 일반 문서는 파일 하나에 200 MiB(209,715,200바이트)까지 첨부할 수 있다. 일반 문서와 이미지 등 다른 종류의 첨부에 적용되는 한도는 화면 안내를 따른다.

- 대화에 파일을 올리고 읽기·표 정리·문서 작성을 부탁한다. 원본과 읽은 글은 자기 계정에 저장되며 다른 계정은 읽거나 검색할 수 없다.
- PDF(스캔 포함), TXT·Markdown·CSV·TSV, 엑셀 XLSX, 워드 DOCX, PPTX, HWP·HWPX를 읽는다. 읽지 못한 문서는 실패 이유를 알린다. 답에는 파일 이름과 쪽·표·셀 등 원문 위치를 근거로 붙인다.
- 엑셀·워드·PPT·HWPX를 만들고 본문을 고쳐 새 파일로 내려받는다. 엑셀 수식은 유지된다. 서버에서 재계산하지 못한 수식은 Excel에서 열어 확인해야 한다. PDF는 새 원고를 정적 문서로 출력하며 발표 자료도 PDF로 만들 수 있다.
- 공문 HWPX 양식을 채우고, HWP는 고친 뒤 HWPX로 저장한다. 워드·PPT·한글의 번역은 본문 글을 바꾸고 서식·그림 관계를 유지한다. 복잡한 변환의 실제 모양은 원래 프로그램에서 확인한다.
- 계약서 두 판은 바뀐 조항과 위험 이유를 원문과 함께 표로 비교한다. 영수증 사진은 경비 엑셀로, 명함은 연락처 표로 정리한다. 알아볼 수 없는 값은 확인 필요로 남긴다.
- “작년 A사 견적서”처럼 내용으로 찾으면 자기 파일에서 후보를 찾고 원문·날짜를 대조한다. 아직 못 읽은 파일은 검색을 끝냈다고 알리지 않는다.
- 본 제품은 한컴의 HWP 문서 파일(.hwp) 공개 문서를 참고하여 개발하였습니다. 한글·한컴·HWP·HWPX는 한컴의 상표이며 한컴과의 제휴를 뜻하지 않는다.

## Jabis 가입·체험·해지
- 소개 화면에서 **구글로 시작하기**를 누르고 Google 계정을 고른다. 처음 온 계정은 14일 무료 체험으로 바로 들어가며 **14일 무료 체험이 시작되었습니다**라는 안내를 한 번 본다. 이미 이용 중인 계정은 기존 자료와 기한으로 들어간다.
- 설정 › 계정의 **Jabis 이용**에서 체험 종료일을 본다. **해지하기**를 누르고 확인하면 대화와 자료를 바꾸는 작업, 예약 작업과 노트 정리가 멈춘다.
- 체험 종료 3일 전부터 서버의 일일 확인 때 **Jabis 이용** 대화에 종료일을 한 번 알린다.
- 체험이 끝나거나 해지하면 자료는 읽기 전용이다. **고객 명단과 기록 내려받기**로 자기 대화·고객 기록과 파일을 ZIP으로 받는다. 보관 기한이 끝나기 전까지 받을 수 있다. ZIP에는 자기 자료만 담기고 모델 이름과 토큰 사용량은 표시되지 않는다.
- 해지 뒤 보관 기간은 90일이다. 체험만 끝났으면 체험 종료일부터 90일 보관한다. 설정에 표시된 보관 종료 뒤에는 서버가 자료를 지운다.
- 체험 종료나 해지 뒤 다시 쓰려면 설정 › 계정의 **이용 문의하기**를 누른다. Jabis에 들어갈 수 없을 때는 로그인 안내 화면의 **이용 문의하기**를 누른다. 두 곳 모두 Aishift 문의 메일을 연다.
- 이 판에는 결제가 연결되어 있지 않다. 카드 등록이나 자동 결제가 된다고 안내하지 않는다.

## Thock이 잘못 들은 말 알리기
- 사용자가 최근 받아쓴 글의 잘못 들린 말을 바로잡으면 `thock_feedback`으로 그 사람의 Thock 계정에 알릴 수 있다. 지금 서비스에 로그인한 Google 계정의 Thock 배운 말에 들어간다. PC가 꺼져 있어도 된다.
- 사용자가 최근 30분 안에 받아쓴 원문과 직접 알려 준 바른 말이 있어야 한다. 원문이 없거나 어느 말을 고치는지 불분명하면 먼저 확인한다. 일반적인 문장 다듬기나 다른 사람의 글에서 학습할 짝을 만들지 않는다.
- 서버는 잘못 들린 말이 전달한 원문에 있는지 확인한다. 현재 서버에는 최근 받아쓰기 기록이 없어 받아쓴 시각과 Thock 출처를 독립적으로 확인하지 못한다.
- 도구의 `stored=true`일 때만 반영됐다고 답한다. 이름·용어로 배울 말이 아니면 `stored=false`로 돌아오며 저장되지 않는다. 실패하거나 결과가 확인되지 않으면 성공했다고 답하지 않는다.
- 다시 로그인하라는 답이 오면 지금 쓰는 서비스에서 로그아웃한 뒤 같은 Google 계정으로 로그인한다. Thock의 받아쓰기·설정·오류는 Thock에서 다룬다.

## 소식과 지켜보기
- 대화에서 공고·경쟁사 뉴스·가격 중 지켜볼 대상과 조건을 정하면 서버가 매일 새벽 확인해 새 건을 오늘 대화에 남긴다. 같은 원문은 다시 알리지 않으며 가격은 같은 값이 이어질 때 알리지 않는다. 중지와 조건 변경도 대화로 한다. 검색이나 연결 실패는 새 건 없음과 구별한다.
- 고객 관리에서는 확인된 고객 정보로 키워드를 준비한다. 키워드는 대화로 보고 고친다. 국내 뉴스와 알리고 지원사업 공고에서 관련 소식을 골라 아침 브리핑에 세 건까지 제안한다. 나머지는 더 보여 달라고 하면 볼 수 있다. 한 고객에게 한 달 두 번까지 제안하며 넘긴 제안도 센다.
- 고객이나 회사의 나쁜 소식은 사용자에게 알아 두실 소식으로만 알리고 고객에게 보낼 글을 만들지 않는다. 확인되지 않은 고객 정보를 발송 문구에 쓰지 않는다.
- 맞춤 소식을 고르면 저장된 고객과 문구로 제품의 발송 확인 상자가 생긴다. 실제 발송은 사람이 상자의 보내기를 눌러야 한다. 발송 PC와 카톡 친구 연결이 필요하다. 제안과 실제 발송 결과는 고객 자료에 이어진다.
- 금융 소식지는 금융 용어·제도·세제·투자 상식·시황을 쉽게 풀어 정기 PDF로 준비한다. 참여 여부, 주기(기본 매월), 받을 고객을 모두·골라서·뺄 사람 중에서 대화로 정한다. 아직 정하지 않은 설정은 임의로 채우지 않는다.
- 발행일이 되면 차트·이미지와 설명, 원고·출처·기준 날짜를 담은 PDF를 만들고 다시 읽어 확인한다. 아침 브리핑에 PDF와 정한 고객의 발송 확인 상자를 올린다. 같은 발행 주기의 호를 중복 제작하지 않는다. 승인 전에는 대화로 고쳐 새로 확인할 수 있다.
- 소식지 설정과 초안 준비는 발송 승인이 아니다. 고객별 상자의 보내기를 눌러야 파일을 보낸다. 카톡 파일 첨부 지원 PC가 필요하며 미지원 PC에서는 준비된 상태로 기다린다. 보냈는지 불확실한 건은 자동으로 다시 보내지 않는다.

## PC에서 하는 일

Krema와 Jabis PC 앱의 설정 › 부가 기능 연동에서 **컴퓨터 조작**을 켜면, 그 계정의 비서가 그 PC의 파일과 프로그램을 다룬다. 여러 PC가 켜져 있으면 어느 PC에서 할지 고른다. PC가 꺼졌거나 그 스위치가 꺼져 있으면 바로 이유를 알린다.

- Windows PC 앱은 `krema.cloud` 로그인 화면의 **Windows PC 앱 받기**, `jabis.cloud` 소개 페이지의 **PC 앱 받기 (Windows)**, 또는 웹 브라우저에서 로그인한 뒤 **설정 › 부가 기능 연동 › Windows PC 앱**의 **PC 앱 받기**(`/api/download`)에서 내려받을 수 있다. 이미 PC 앱 창에서 보고 있을 때는 이 단추가 보이지 않는다.

- 파일을 찾고 읽거나 PC와 서버 사이에서 옮길 수 있다. Krema에서는 PC의 파일을 고칠 수 있다. PC 명령·파일 변경·마우스와 키보드 입력은 개발자와 직원이 고른 명령 실행 승인 방식을 따른다.
- Jabis의 PC 작업에는 보호 기능을 지원하는 Windows PC 앱이 필요하다. 업데이트 안내가 나오면 PC 앱을 최신 버전으로 업데이트한 뒤 작업을 다시 요청한다.
- Jabis는 PC에 새 파일을 저장할 수 있다. 같은 경로에 파일이 있으면 다른 이름을 지정한다. 비서는 파일 도구로 기존 파일을 고치거나 덮어쓸 수 없다. 연결된 PC 프로젝트의 Git 브랜치 상태를 볼 수 있으며, 브랜치 전환과 새 브랜치 만들기는 사람이 직접 한다.
- Jabis의 PowerShell과 오래 걸리는 명령은 승인 카드 없이 별도의 임시 폴더에서 실행한다. Windows의 낮은 무결성 수준(보통 권한 파일의 수정·삭제를 막는 Windows 권한)이 적용된다. 명령에서 만든 결과 파일은 성공 뒤 사용자 폴더의 **Jabis 결과** 폴더에 저장된다. 같은 이름의 결과 폴더가 있으면 번호를 붙여 새 폴더를 만들고 이전 결과를 보존한다.
- 오래 걸리는 명령은 작업 번호를 바로 돌려준다. 비서에게 그 작업의 상태와 출력을 묻거나 멈춰 달라고 한다. **멈추는 중**은 PC가 종료를 확인하기 전이다. 멈춤·실패 뒤 다시 실행하면 새 번호를 받는다. 긴 작업은 PC 한 대에서 세 개까지 함께 돈다. 끝나면 그 일을 시킨 대화로 알림이 온다.
- 화면 찍기, 창 목록·앞으로 가져오기, 화면 글자 읽기, 마우스·키보드 입력을 한다. 창 메시지를 받는 프로그램에는 포인터를 움직이지 않고 입력할 수도 있다.
- 화면을 조작하는 동안 **PC 조작 중** 표시와 **지금 멈추기** 단추가 뜬다. 그 순간 사람이 마우스나 키보드를 쓰면 그 조작 하나만 멈추고, 손을 떼면 다시 할 수 있다. **지금 멈추기**를 누르면 화면 조작이 모두 멈추고, 다시 하려면 컴퓨터 조작을 껐다 켠다. 화면을 찍는 일과 화면을 쓰지 않는 긴 명령은 사람 입력 때문에 멈추지 않는다.
- 웹사이트 작업은 **웹 브라우저 조작**을 켠 PC의 전용 브라우저로 한다. 로그인 단계는 사람에게 넘기고, 사람이 끝났다고 하면 되찾는다.
- Jabis 비서는 앞에 표시된 창이나 입력 대상 창이 카카오톡, 문자팝 발송 화면, PowerShell·명령 프롬프트·Windows 터미널·실행 창, Jabis 앱·웹 화면이면 마우스·키보드 입력을 멈춘다. 다른 창은 조작할 수 있다. 비서의 웹 브라우저 조작에서도 Jabis 웹 화면을 열거나 조작할 수 없다.
- 프로젝트 폴더 선택의 **위치**에서 켜진 PC를 고르면 그 PC의 드라이브와 사용자 폴더를 고를 수 있다. 파일 보기·@파일 선택·Git 브랜치는 PC의 원본 폴더를 사용한다. 서버 폴더와 서로 복사하거나 맞추지 않는다. PC가 꺼지면 그 폴더는 열리지 않는다.
- 답 속 PC 파일을 PC 앱에서 누르면 확인 뒤 그 PC의 기본 프로그램으로 연다. 서버 파일은 로그인한 소유자만 문서로 보거나 내려받는다. PC 앱의 Windows 알림을 누르면 그 앱의 해당 대화가 열린다.


### 실행 중인 PC 작업에 입력 보내기

- 비서에게 백그라운드 PC 작업의 번호와 보낼 글을 말한다. 입력 기능을 지원하는 PC 앱에서 작업이 실행 중이고 입력을 받을 준비가 돼 있어야 한다.
- Krema에서는 사람이 승인한 작업에 입력을 보낼 수 있다. Jabis에서는 작업을 시작한 대화에서만 입력을 보낼 수 있다. Jabis 작업을 다시 실행한 뒤에도 최초 실행을 요청한 대화에서 새 작업 번호로 입력을 보낸다. 연결이나 권한이 끊겼거나 작업이 끝났으면 비서가 사유를 알린다. 로그인 정보처럼 비밀인 값은 PC 화면에서 직접 입력한다.
- 입력 결과가 대기 중이면 비서가 입력 요청의 상태를 확인한다.

## 카톡과 문자 보내기

여러 명에게 보내려면 대화에서 카테고리와 포맷을 먼저 정하고 **포맷 승인**을 누릅니다. 보내기마다 받을 사람 수·샘플·예약 시각·첨부·이모티콘·문자 번호를 확인한 뒤 **보내기**를 누릅니다. 비서의 말만으로 승인되지 않습니다. **받는 사람과 글 모두 보기**로 전체 내용을 확인할 수 있습니다.

Jabis에서 카톡을 보내려면 최신 Jabis PC 앱을 사용하고 같은 PC에서 카카오톡에 로그인해 주세요. Jabis는 등록된 방 이름과 열린 방 제목이 정확히 같을 때 보냅니다. 본인에게 보내려면 방 이름을 **나와의 채팅**으로 지정해 주세요. Jabis가 카카오톡의 내 프로필에서 그 방을 엽니다.

승인한 묶음은 한 명씩 간격을 두고 나가며 고객 기록에 남습니다. 확인 상자에서 **진행 새로 보기**, **다음 발송부터 멈추기**, **이어 보내기**, **예약 · 남은 발송 취소**를 누릅니다. PC에 이미 건넨 한 건은 끝날 수 있습니다. **확인 필요**인 건은 다시 보내지 말고 실제 카톡이나 문자 서비스 발송 내역을 확인합니다.

새 Windows 카카오톡(Qt판)에서는 Jabis로 글을 보낼 수 있습니다. 파일 첨부와 이모티콘 발송은 기존 Windows 카카오톡에서 지원합니다. 지원하는 판에서는 승인한 사진·PDF 등과 같은 파일인지 확인한 뒤 PC에 내려받아 카톡에 붙입니다. 무료 이모티콘은 발송 당일 그 방에서 읽은 그림에서 고릅니다. 고른 뒤 화면이나 파일이 바뀌면 보내지 않고 다시 확인합니다. 잘린 이름·동명이인·이름 변경·삭제·차단·수신 거절이 확인된 고객에게는 보내지 않습니다. 친구 이름을 구별한 뒤 목록을 다시 읽도록 요청합니다.

서버 예약은 PC가 꺼져 있으면 켜진 뒤 이어 갑니다. 카톡 자체 예약과 실제 PC 발송은 따로 확인해야 합니다. 비서에게 읽을 방과 답장 알림 규칙을 정해 주면 채팅 목록의 마지막 시각·안 읽은 수·생일·새 친구·답장을 관측하고 오늘 대화에 알립니다.

문자는 문자팝 개인회원으로 가입해 본인 인증한 휴대폰 번호를 발신번호로 씁니다. 비서가 가입 화면을 열어 드립니다. 로그인과 인증을 마쳤다고 알려 주시면 비서가 문자팝의 발신번호 설정에서 등록된 번호를 확인합니다. Krema에서는 일반 문자 화면에서 고를 수 있는 발신번호도 확인합니다. 문자 비용은 문자팝에 직접 냅니다.

Jabis PC 앱의 **설정 › 부가 기능 연동**에서 **웹 브라우저 조작**을 켜 주세요. 문자 발송 화면에서 추가 인증을 요구하면 직접 문자팝을 열어 인증을 마칩니다. 인증을 마쳤다고 알려 주시면 Jabis가 확인 상자를 새로 띄웁니다. 받는 사람의 번호와 글이 맞으면 **보내기**를 누릅니다. 그러면 PC 앱이 확인한 내용으로 문자팝에서 발송합니다. 카톡이 전송되지 않았음을 확인하고 문자로 바꿀 때도 새로 승인합니다. **확인 필요**인 카톡은 이미 갔을 수 있으므로 문자로 자동 대체하지 않습니다.

고객의 연락 금지는 PC가 꺼져 있어도 기록할 수 있습니다. 다시 연락하려면 고객 대응이 유효한지 확인하고 고정 확인 상자의 **연락 재개**를 사용자가 눌러야 합니다. 친구 목록에 다시 나타나도 연락 금지를 자동으로 풀지 않습니다.
