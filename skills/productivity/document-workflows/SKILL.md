# 문서로 하는 일

## 계약서 두 판

두 파일을 각각 `document_read`로 읽는다. 모델이 조항의 의미를 비교해 `조항 | 이전 원문·위치 | 새 원문·위치 | 바뀐 내용 | 위험 이유·확인할 점` 표로 답한다. 순서가 옮겨진 조항과 문구만 바뀐 조항을 구분한다. 위험은 자동 키워드 판정이 아니라 두 판과 사용자 목적의 맥락으로 설명한다. 한쪽 원문이 없거나 읽지 못했으면 비교를 완료로 보고하지 않는다. 사용자가 파일을 원하면 `document_write`로 표를 저장한다.

## 영수증·명함

첨부 사진이나 `document_read`가 반환한 쪽 이미지를 모델의 그림 읽기로 읽는다. 각 행에 원본 사진 이름·쪽 위치를 남긴다. 영수증은 날짜·사용처·항목·금액·확인 필요를, 명함은 이름·회사·직책·전화·이메일·확인 필요를 원문에 있는 만큼 정리한다. 판독 불가 값은 추정하지 않고 확인 필요로 남긴다. 금액의 실제 수치가 확인되지 않으면 합계에 몰래 넣지 않는다.

그림 읽기 도구에는 접근 가능한 실제 경로나 이미지 주소가 필요하다. 첨부의 표시 이름은 경로가 아니므로 파일을 찾지 못하면 같은 이름으로 반복 호출하지 말고 원본 참조를 확인한다. 대화에 직접 실린 그림은 그 그림에서 읽는다.

결과는 `document_write`의 엑셀 셀로 저장한다. 합계는 수식으로, 전화번호는 문자열로 전달한다. 다시 읽어 각 원문과 값·합계 범위를 대조한다. 연락처 표를 만들었다고 CRM 등록이나 메시지 발송까지 진행하지 않는다. 그것은 별도 확인 경로가 맡는다.

## 서식 보존 번역

해당 형식의 `docx`·`powerpoint`·`hangul-documents` 스킬을 읽는다. `document_read`의 위치별 문맥과 `text_units`를 함께 보고 모든 ID를 번역한다. `document_write`에 원본·체크섬·ID별 번역을 주면 텍스트 노드만 바꾸고 서식을 유지한다. 누락 ID나 빈 번역은 오류이므로 결과를 지어내지 말고 누락 내용을 보완해 한 번만 다시 실행한다. 다시 실패하면 이유와 남은 작업을 알린다. 저장 후 재읽기에서 새 글·표·그림 관계를 확인하고 파일 링크를 준다.
